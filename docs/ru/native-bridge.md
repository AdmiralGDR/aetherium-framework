# Нативный мост (JNI / C++ с порядком отката на FFM)

*Модуль: `aetherium-native` · Русский. Английская версия: [`../en/native-bridge.md`](../en/native-bridge.md).*

## 1. Назначение

Некоторые операции, нужные Aetherium, невыразимы на чистой Java с приемлемой
стоимостью: прямая работа с memory-mapped буферами, привязка потоков к ядрам на
уровне ОС, быстрое хеширование байтов классов и низколатентное зондирование нативных
структур данных загрузчика. Нативный мост предоставляет их через
**посреднический интерфейс с белым списком** — моды никогда не вызывают нативный код
напрямую.

## 2. Выбор пути и порядок отката

Мост *не* зашит на один механизм. Во время загрузки он зондирует возможности и
выбирает наивысший доступный уровень, фиксируя выбор в отчёте запуска:

```
 FFM (java.lang.foreign, preview)   ← предпочтительно на GraalVM 21
        │  недоступно?
        ▼
 JNI (классические native-методы + .so) ← переносимый откат
        │  недоступно?
        ▼
 чисто-Java прослойка                ← корректность важнее скорости
        │  недоступно?
        ▼
 функция отключена (корректно)       ← никогда не падаем при запуске
```

**FFM** (`java.lang.foreign`, preview в 21) предпочтителен: без рукописного JNI-клея,
downcall-ы на основе `MethodHandle`, встраиваемые JIT, и память в области видимости
`Arena` с детерминированным освобождением. **JNI** остаётся полностью поддерживаемым
откатом там, где нужный символ или особенность платформы недостижимы через FFM.
Чисто-Java прослойка гарантирует *корректность*, даже когда недоступен ни один
нативный уровень.

## 3. Сторона C++ (`src/main/cpp`)

- Компилируется в единый `libaetherium_native.so` (база Linux x86-64).
- Экспонирует **узкий версионированный C ABI** — плоскую таблицу функций, а не
  поверхность классов C++ — чтобы и FFM-downcall-ы, и JNI-привязки целились в одни
  символы.
- Все точки входа валидируют аргументы и возвращают структурированные коды ошибок; ни
  одно исключение не пересекает границу. Ненулевой код запускает лестницу отката на
  стороне Java.

## 4. Контракты `O(1)` и памяти

- Каждая мостовая операция — вызов за константное время: связанный FFM `MethodHandle`
  или привязанный JNI method id, разрешённый **однократно** при загрузке, затем
  переиспользуемый.
- Нативной памятью владеет ограниченная `Arena` на логическую область; освобождение
  детерминированное и своевременное — без опоры на финализацию GC, без утечек между
  тиками.
- Никаких аллокаций на вызов на «горячем пути»; буферы преразмеряются при загрузке.

## 5. Безопасность (триада CIA)

- **Конфиденциальность** — мост экспонирует только явный белый список нативных
  возможностей. Нет универсальной точки входа «вызвать произвольный символ». Пути и
  адреса хоста вычищаются из любой диагностики, видимой модам.
- **Целостность** — валидация аргументов с обеих сторон границы; C ABI версионирован,
  и сторона Java отказывается от несовпадающей библиотеки вместо вызова в неё.
  Нативные буферы проверяются на границы перед использованием.
- **Доступность** — нативный сбой локализуется: структурированные коды ошибок (по
  возможности без сырых сигналов), лестница отката из и `Arena` на область,
  чисто освобождаемые при сбое. Отсутствующий или сломанный `.so` деградирует до
  чисто-Java прослойки, но не до краха JVM.

## 6. Заметки по сборке и упаковке

- Тулчейн C++ и артефакт `.so` производятся отдельной задачей Gradle (будет
  подключена на следующем этапе); `.so` исключён из VCS (см. `.gitignore`) и собирается
  воспроизводимо.
- FFM-downcall-ы выполняются с `--enable-preview` на GraalVM 21; флаг preview
  устанавливается централизованно сборкой, а не помодульно.
