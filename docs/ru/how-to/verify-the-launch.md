# Как доказать, что ваш мод запускается на фреймворке

*Русский. Английская версия: [`../../en/how-to/verify-the-launch.md`](../../en/how-to/verify-the-launch.md).*

*Практическое руководство для авторов модов и разработчиков фреймворка. Оно отвечает на главную просьбу
— «сделать так, чтобы игра запускалась, и дать нам точно и чётко это проверять». Про устройство
проверок читайте [artifact-roles](../explanation/artifact-roles.md) и [verify](../explanation/verify.md).*

Есть два уровня доказательства. Начните с офлайн-барьера — он мгновенный и не требует игры; переходите к
реальному серверу, только когда нужна абсолютная истина.

## 1. Офлайн-барьер (мгновенно, без игры и аккаунта)

```
./gradlew check          # запускает verifyJar + bootSmoke среди прочего
# или только проверки артефактов:
./gradlew verifyJar
```

`verifyJar` прогоняет `ArtifactVerifier` по *поставляемым* jar и своим же ASM проверяет, что:

- **ни один пакет не пересекает границу артефактов** (`AE-MODULE-CLASH`) — дефект графа модулей, который
  раньше ронял игру до любого окна. Если два модуля в поставляемом наборе экспортируют один пакет — падает и
  называет его; чистый прогон печатает
  `✓ no-cross-artifact-package-clash — no package is exported by two modules across the shipped set`;
- загрузчик самодостаточен, boot-путь без preview, нет встроенных платформенных библиотек, а роли
  `MOD` / `GAMELIBRARY` верны.

Это то, что вы запускаете в CI. Оно ловит блокер запуска за ~1 с без скачивания Minecraft.

## 2. Окончательное доказательство (реальный headless-сервер)

Когда хотите *увидеть* старт игры со своим модом — загрузите реальный выделенный сервер NeoForge. Ни дисплей,
ни аккаунт Minecraft не нужны: выделенный сервер headless, а блокер запуска происходит при разрешении модулей,
до любого окна.

```
# фреймворк + встроенный testmod:
./scripts/launch-check.sh

# фреймворк + ВАШ мод:
./scripts/launch-check.sh build/aetherium-test-server /путь/к/your-mod.jar
```

Скрипт собирает поставляемые jar, при первом запуске устанавливает сервер NeoForge 1.21.1 (скачивает
Minecraft + NeoForge — нужен интернет, однократно), кладёт `aetherium-transformer` + `aetherium-loader` +
любые переданные моды в `mods/`, загружается headless, авто-останавливается и грепает лог. Успех печатает:

```
  ✓ no module ResolutionException
  ✓ Aetherium Framework is in the mod list
  ✓ server reached Done (started)
RESULT: LAUNCH OK ✓
```

Переопределите JVM через `AETHERIUM_JAVA=/путь/к/java21`, а версию NeoForge — через `AETHERIUM_NEOFORGE=…`.
Полный лог сервера остаётся в `<server-dir>/launch-check.log` для разбора.

## 3. Доказать, что поведение машины реально диспатчится

Если ваш мод объявляет `@AetheriumBlock(behavior = MyLogic.class)`, докажите, что оно тикает в игре: загрузите
сервер как выше, затем в его консоли поставьте блок и прочитайте его данные обратно —

```
setblock 0 100 0 yourmod:your_machine
data get block 0 100 0
```

Тикающая машина показывает рост сохранённого состояния, напр. `{aeth_longs: {ticks: 598L}, aeth_age: 598L}` —
колбэк `tick(ctx)` сработал 598 раз, и счётчик сохранился в NBT. См.
[game-integration → диспатч машин](../explanation/game-integration.md).
