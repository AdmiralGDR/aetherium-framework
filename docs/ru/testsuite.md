# Набор тестов Chaos Engineering

*Русский. Английская версия: [`../en/testsuite.md`](../en/testsuite.md).*

`aetherium-testsuite` намеренно атакует фреймворк, чтобы доказать сохранение гарантий
безопасности при катастрофическом одновременном сбое модов. Зависит от `core`,
`bytecode` и `native`; ни один продакшен-модуль от него не зависит.

## Что он делает

Синтезирует враждебные «моды» и передаёт их в **реальный** `BytecodeEngine` и
**реальный** слой FFM, затем утверждает единственный инвариант: **фреймворк локализует
каждый сбой и JVM никогда не падает** (ноль escape).

### Порча байт-кода (`ChaosMutators`)

| Вид | Внедрённый дефект |
|-----|-------------------|
| `VALID` | исправный класс (контрольный образец) |
| `TRUNCATED` | файл класса обрезан пополам |
| `BITFLIP` | случайные байты перевёрнуты после заголовка |
| `HEADER_CORRUPT` | разбита сигнатура `0xCAFEBABE` |
| `TYPE_CONFUSION` | возвращает `int` там, где объявлена ссылка |
| `STACK_UNDERFLOW` | `POP` на пустом стеке |

Движок обязан прочитать-или-упасть, трансформировать-или-упасть, верифицировать-или-упасть,
и при **любом** сбое откатиться к входным байтам плюс структурированный `Diagnostic` —
никогда не бросать. Харнесс также устанавливает трансформер, случайно бросающий (~30%),
чтобы нагрузить путь исключения трансформера даже на валидном входе.

### Нативный / FFM хаос (`NativeChaos`)

Использует только **охраняемое FFM** злоупотребление — никогда дикий указатель (это был
бы настоящий неперехватываемый `SIGSEGV`):

- **use-after-free** — обращение к сегменту после закрытия его `Arena` → `IllegalStateException`.
- **выход за границы** — чтение далеко за концом сегмента → `IndexOutOfBoundsException`.
- **давление аллокаций** — выделить и бросить множество сегментов для нагрузки аллокатора.

Каждый случай должен быть локализован как перехватываемое Java-исключение.

## Параллелизм

`ChaosHarness` выполняет каждую задачу на `Executors.newVirtualThreadPerTaskExecutor()` —
по одному виртуальному потоку на имитируемый мод — чтобы воспроизвести нагрузку **500+
тяжёлых модов**, инициализирующихся одновременно. По умолчанию 600 модов + ~100 нативных
задач (≈700 виртуальных потоков).

## Запуск

```bash
aetherium-cli chaos          # по умолчанию 600 модов
aetherium-cli chaos 1000     # масштабировать
./gradlew :aetherium-testsuite:run --args="600"   # автономно
```

## Критерий прохождения

`ChaosReport.passed()` требует `escaped == 0`, `nativeEscaped == 0` и полного учёта
(`transformedOk + reverted == modTasks`). Код возврата `0` при успехе. Показательный
прогон: 600 байт-код задач (≈527 безопасно откатились, ≈73 трансформированы) + 100
нативных задач (100 локализованы), **0 escape, PASS**.
