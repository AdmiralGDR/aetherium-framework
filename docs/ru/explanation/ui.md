# UI — декларативный Flexbox-подобный GUI-фреймворк

*Русский. Английская версия: [`../en/ui.md`](../../en/explanation/ui.md).*

`aetherium-ui` — кроссплатформенный GUI-фреймворк **без импортов Minecraft**. Мод описывает экран
декларативно один раз; загрузчик его рисует. Раскладка, отрисовка и обработка кликов работают офлайн —
самотест строит, раскладывает, «рисует» и кликает экран без запущенной игры.

## Создание экрана

Дерево виджетов строится фабрикой `Ui` — DSL в духе React/Flexbox:

```java
Widget<?> ui = Ui.column()
    .padding(8).gap(4)
    .background(UiColor.rgb(0x202024))
    .align(AlignItems.STRETCH)
    .children(
        Ui.label("Faction: Iron Vanguard").color(UiColor.WHITE),
        Ui.row().gap(4).children(
            Ui.button("Deposit", this::deposit).grow(1f),
            Ui.button("Close", this::close).grow(1f)),
        Ui.spacer().grow(1f));
```

`column`/`row` — flex-контейнеры; `grow(1f)` заставляет детей делить свободное место (две кнопки делят
строку поровну); `align(STRETCH)` растягивает детей по поперечной оси. Каждый модификатор типобезопасен и
цепочечный, потому что `Widget` самотипизирован.

Для полного экрана наследуйте `AetheriumScreen` и верните дерево из `build()`:

```java
public final class FactionScreen extends AetheriumScreen {
    public String title() { return "Faction"; }
    public Widget<?> build() { return /* дерево выше */; }
}
```

## Как это рисуется

`FlexLayout` вычисляет абсолютный `Rect` для каждого виджета (однопроходный Flexbox-солвер: базовые
размеры → распределение `grow` → `justify` → `align`/`STRETCH` по поперечной оси). Затем `UiRuntime`
рисует разложенное дерево через SPI `UiRenderer` из двух методов (`fillRect` + `drawText`) и
диспетчеризует клики верхней `Button`. Измерение текста скрыто за `UiMetrics` (загрузчик даёт точные по
шрифту метрики; офлайн используется значение по умолчанию).

Интеграция с загрузчиком — один тонкий адаптер, и с Фазы 22 он **реализован** (итерация 2, ): загрузчик
поставляет `NeoForgeUiRenderer` (поверх `GuiGraphics`: `fill`/`drawString`/`enableScissor`/`disableScissor`),
`NeoForgeUiMetrics` (поверх `Minecraft.getInstance().font` — точные ширины; офлайн 6px/символ врёт для
кириллицы) и `AetheriumScreenAdapter extends Screen`, вызывающий
`UiRuntime.render/click/keyPressed/charTyped/scroll`. Мод открывает экран через
`AetheriumUi.open(AetheriumScreen)` — разрешается через `ServiceLoader`, как `Platform.bridge()`, и no-op вне
клиента. Ни один тип Blaze3D не попадает во фреймворк.

С Фазы 22 `FlexLayout` также **сжимает** детей при нехватке места (flex-shrink; `Widget.shrink(0)` — не
сжимать), `ScrollPanel.intrinsicWidth` симметричен по высоте, позиция прокрутки переживает перестройку
(`ScrollPanel.child(...)` + отложенное смещение), а `UiRuntime.audit(LaidOut)` ловит вылет ребёнка за
пределы родителя.

## Доказательство

```bash
aetherium ui
```

Самотест раскладывает экран фракции во вьюпорте 200×120, подтверждает, что две кнопки `grow(1)` делят
строку, рисует его через записывающий рендерер (3 заливки, 3 отрисовки текста) и диспетчеризует клик,
вызывающий ровно обработчик нужной кнопки — всё без запущенной игры.

## Фаза 23 (отзыв, итерация 3)

`UiRuntime.audit(root, metrics)` также ловит подпись шире своего бокса; `Widget.minContentSize(true)` не даёт
flex-shrink обрезать метку ниже содержимого. `Text.align(START|CENTER|END)`. `ScrollPanel.hasMeasured()`
отличает «нечего прокручивать» от «ещё не измерено»; `ScrollPanel.scrollbar(true)` рисует дорожку и ползунок,
`PAGE_UP`/`PAGE_DOWN` прокручивают страницу. `AetheriumUi.close()` симметричен `open()`; адаптивный
`AetheriumScreen.build(Rect viewport)`.

## Фаза 27 (отзыв ) — готовый GUI больше не размывается повторно

— первый отчёт из сессии, где UI был реально виден в игре, и он нашёл рендер-баг высокой важности:
**каждый экран Aetherium был замылен** — не мир за ним, а собственные плоские `fill`-прямоугольники и текст мода.
Доказано по байткоду: `AetheriumScreenAdapter.render` заканчивался вызовом `super.render(...)`, а **первая
инструкция `Screen.render` в 1.21.1 — повторный `renderBackground()`** → `renderBlurredBackground` →
`GameRenderer.processBlurEffect`, постобработка главного render target, где к этому моменту уже нарисован
интерфейс. Адаптер размывал мир (верно), рисовал scrim + UI, а затем размывал *всё нарисованное*.

Исправление — одна строка: **не звать `super.render`.** Адаптер не регистрирует ванильных виджетов, поэтому
единственный другой эффект `Screen.render` — перебор `this.renderables` — пустой; теперь адаптер перебирает
`renderables` напрямую (поддержка ванильных виджетов сохранена) и не запускает фон повторно. Единственное
задуманное размытие мира в начале `render` остаётся.

Поскольку размытие жило внутри класса фреймворка, который мод заменить не может, обхода не было — поэтому
исправление идёт с проверкой. Проверка **`AE-UI-BLUR`** в `ArtifactVerifier` (в `verifyJar` + `bootSmoke`, то
есть в `./gradlew check`) утверждает своим же ASM по поставляемому jar, что `AetheriumScreenAdapter.render` не
содержит `INVOKESPECIAL Screen.render` — ровно тот приём, о котором просил отзыв. А реальный запуск клиента под
Xvfb (`scripts/launch-check-client.sh`, см. [verify](verify.md)) теперь доказывает, что GUI действительно
рисуется.

## Фаза 28 (отзыв ) — HUD-оверлеи и отказ от затемнённого фона

**HUD (рисуем поверх игры без экрана).** `Screen` ставит ввод на паузу и затемняет мир; **HUD** — нет.
`AetheriumHud` — постоянное всегда-включённое дерево виджетов (`build(Rect viewport)` + переключатель
`visible()`), которое мод регистрирует через `AetheriumUi.addHud(hud)` (и снимает `removeHud`). Загрузчиковый
`ClientHudRenderer`, зарегистрированный на `RenderGuiEvent.Post` NeoForge, рисует каждый видимый HUD каждый кадр
тем же `UiRuntime` + `NeoForgeUiRenderer`, что и экраны, — поверх живого `GuiGraphics`, без scrim и без перехвата
ввода. Каждый HUD — в try/catch, поэтому один сбойный оверлей не ломает кадр. Вне клиента всё это no-op (список
пуст), поэтому мод зовёт `addHud` безусловно, а дерево виджетов HUD раскладывается и рисуется headless через
`RecordingUiRenderer` — доказуемо юнит-тестом без игры.

**`opaqueBackground()` ().** Раньше каждый экран Aetherium рисовал scrim на весь viewport — верно для
панели настроек, неверно для лёгкого диалога поверх мира. `AetheriumScreen.opaqueBackground()` (по умолчанию
`true`) — отказ: верните `false`, и адаптер не рисует **ни** размытие мира, **ни** scrim, поэтому панель лежит
над полностью видимым миром. Ввод по-прежнему перехватывается; меняется только фон. Прямой рендер `renderables`
не изменён, поэтому `AE-UI-BLUR` по-прежнему держится.

**Измерение согласовано с размещением ().** Собственный размер `Container` раньше учитывал только
*intrinsic*-размеры детей, игнорируя явные `width()`/`height()` — хотя `FlexLayout` уважает эти спеки при
*размещении*. Полоса с одним лишь `height(4)` (intrinsic-высота `Spacer` — 0) ничего не давала родителю; тот не
резервировал ряд, и полоса рисовалась поверх соседа. Помощники измерения теперь берут `max(spec, intrinsic)`,
поэтому ребёнок с явным размером резервирует своё место.

**`audit` ловит перекрытие соседей ().** `UiRuntime.audit` проверял вложенность и обрезку текста, но
раскладка с двумя соседями на одних пикселях проходила чисто — ровно дефект из Теперь добавлено третье
правило: прямоугольники соседей внутри одного контейнера не должны пересекаться (O(n²) по прямым детям, чистая
геометрия). Flex-контейнер раскладывает детей плиткой, поэтому любое перекрытие — дефект; так «зелёно» значит
«раскладка верна», что и тестируют потребители в CI.
