# Суверенный Щит — защита модов и авторов от реверс-инжиниринга и анализа ИИ

`aetherium-shield` — это байткод-**протектор** времени сборки/загрузки для *собственных* скомпилированных
классов автора мода. Цель явная и двойная: усложнить реверс-инжиниринг мода человеком **и усложнить анализ
или декомпиляцию автоматическим инструментом — включая LLM/ИИ.** Защита подключается по желанию, и за
лицензию своего мода отвечает сам автор.

## Почему отдельный акцент на ИИ

Классическая обфускация проектировалась против аналитиков-людей. Автоматические декомпиляторы и, всё чаще,
LLM меняют модель угроз: модель за секунды поглощает целый jar и восстанавливает замысел из трёх сигналов,
которые обычный байткод отдаёт бесплатно —

1. **Слова** — строковые литералы (сообщения об ошибках, ключи конфигурации, URL, registry-id) читаются
   дословно как семантические подсказки.
2. **Имена** — имена классов, пакетов и переменных — скелет модели для «что это делает».
3. **Форма** — чистый, приводимый управляющий поток позволяет модели восстановить исходную структуру.

Щит удаляет или портит каждый сигнал, поэтому автоматическому проходу остаются непрозрачный «байтовый салат»,
синтетические имена и запутанный поток. Это глубокая эшелонированная защита: ни один слой не непробиваем, но
вместе они поднимают стоимость — для человека и машины — далеко выше чтения plaintext-jar.

## Слои

Каждый проход — независимый `ClassTransformer` и работает **внутри верификационной песочницы
`aetherium-bytecode`**, поэтому проход, который дал бы невалидный байткод, откатывает *именно этот класс* к
оригиналу, а сборка не ломается. Корректность важнее защиты.

| Проход | Класс | Отнимает у аналитика… | Примечания |
|---|---|---|---|
| Удаление отладки | `DebugStripTransformer` | номера строк + имена переменных/параметров автора | убирает `SourceFile`, `LineNumberTable`, `LocalVariableTable`, `MethodParameters` |
| Шифрование строк | `StringEncryptionTransformer` | **«что»** — каждый читаемый литерал | каждый `LDC "s"` → `ldc <шифр>; ldc <ключ>; invokestatic decode`; plaintext не существует в файле |
| Обфускация потока | `ControlFlowObfuscator` | **«как»** — чистый приводимый поток | вставляет непрозрачный предикат + мёртвый блок `throw` в каждый метод |
| Переименование | `Renamer` | **семантическую карту** — имена классов/пакетов/членов | классы → `o/a`, `o/b`…; приватные методы/поля → `a`, `b`…; keep-list сохраняет разрешение по имени/сервису |
| Манифест целостности | `IntegrityManifest` | правку без обнаружения | SHA-256 на класс; несовпадение доказывает, что jar правили после защиты |
| Водяной знак автора | `WatermarkAttribute` | анонимность утечки | невидимый атрибут класса `author\|timestamp` — украденный jar остаётся трассируемым к автору |

### Шифрование строк подробно

Крупнейшая утечка в jar мода — plaintext. Проход XOR-шифрует каждый литерал ключом, кладёт в пул констант
**только шифртекст** и переписывает загрузку в вызов крошечного синтетического декодера (`$aeth$x`),
добавляемого в класс. Читаемый текст существует лишь на миг в памяти при использовании — `grep` не находит
ничего, а модель видит вызов декодера над непрозрачными байтами.

> Оговорка: `static final String`-константа компиляции *встраивается javac* в местах использования (где этот
> проход её шифрует), но объявляющее поле также хранит копию `ConstantValue`. Не помечайте настоящий секрет
> как константу компиляции; используйте обычное поле или возврат метода.

### Переименование и keep-list

Переименование — самый сильный проход против анализа и самый опасный, потому что всё, что разрешается *по
имени* в рантайме, должно уцелеть. `KeepList` закрепляет рантайм фреймворка (`org/aetherium/**`),
сгенерированную точку входа `@AetheriumInit` и каждый класс из файла `META-INF/services`. Переименовываются
только **приватные** методы и поля (нет внешних ссылок, нет переопределений), а **записи (records) не
трогаются** (имена компонентов/аксессоров/конструктора несут смысл). Все ссылки — включая method handle за
лямбдами — переписываются согласованно, поэтому результат по-прежнему загружается и работает.

### Целостность и водяной знак

Манифест целостности (`shield-integrity.txt`, реестр `binaryName=sha256`) превращает тихую правку в
обнаружимое событие — взломанный jar, внедрённый бэкдор или обойдённая проверка меняют хэш. Водяной знак —
нестандартный атрибут класса, который JVM игнорирует; он не упоминается кодом, поэтому наивное удаление его
не заденет, и он делает утёкший jar трассируемым к автору — защита *автора*, а не только кода.

## Использование

### Gradle (рекомендуется)

```kotlin
aetherium {
    version = "1.0.0-SNAPSHOT"
    shield = true
    shieldAuthor = "a downstream mod"
    // shieldRename = true   // продвинутое: также переименовать классы/приватные члены (нужен полный keep-list)
}
```

Плагин регистрирует задачу `aetheriumShield`, от которой зависит `jar`. Она работает в **отдельной** JVM
(рантайм фреймворка — `--enable-preview`, который демон Gradle грузить отказывается) и обфусцирует
скомпилированные классы на месте перед упаковкой. Переименование классов **выключено по умолчанию** — оно
двигает файлы и сломало бы разрешение по имени/сервису без полного keep-list.

### CLI

```console
$ aetherium protect build/classes/java/main --author "a downstream mod"      # на месте, без переименования (безопасно)
$ aetherium protect build/classes/java/main --author "a downstream mod" --rename
$ aetherium shield        # прогнать сквозной self-test
```

### Программно

```java
Shield.Result r = Shield.protect(classesByBinaryName, ShieldOptions.standard("a downstream mod"),
                                 new KeepList().keepService("com.example.MyMod"), verifyLoader);
r.protectedClasses();   // binaryName -> защищённые байты
r.integrity();          // манифест защиты от правок
r.revertedClasses();    // сколько откатилось (валидны, но без обфускации)
```

## Гарантии (доказаны `aetherium shield` / `ShieldSelfTest`)

- Plaintext зашифрованной строки **отсутствует** в защищённых байтах.
- Отладочная информация удалена.
- Класс, переименованный в непрозрачное имя, **всё ещё загружается и работает**, корректно декодируя строки в рантайме.
- Правка одного байта **отклоняется** манифестом целостности.
- Водяной знак автора **извлекаем** из защищённых байтов.
- Защита негодного ввода (мусорные байты) **откатывается чисто** с диагностикой — без краха.

## Пределы

Обфускация поднимает стоимость; это не шифрование работающей программы. Настойчивый аналитик с живой JVM
всё ещё может наблюдать поведение, а декодер строк присутствует в байткоде. Задача щита — сделать *массовое,
автоматическое* извлечение (дешёвый путь, которым идёт ИИ) дорогим, а кражу — *трассируемой* и *обнаружимой*.
Используйте вместе с `aetherium-security` (изоляция по способностям) для глубокой защиты.
