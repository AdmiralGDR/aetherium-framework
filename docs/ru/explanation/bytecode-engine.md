# Движок манипуляции байт-кодом (на основе ASM)

*Модуль: `aetherium-bytecode` · Русский. Английская версия: [`../en/bytecode-engine.md`](../../en/explanation/bytecode-engine.md).*

## 1. Назначение

Движок переписывает классы модов во время загрузки так, чтобы вызовы API,
независимые от загрузчика, понижались до конкретных точек вызова с диспетчеризацией
`O(1)` (см. `ARCHITECTURE.md` –). Он построен на [OW2 ASM](https://asm.ow2.io/) —
выбран вместо Javassist/ByteBuddy за модель посетителей с нулевыми накладными
расходами и точный контроль над пулом констант и картами кадров стека, что важно для
гарантий верификации ниже.

## 2. Конвейер

```
 сырой byte[] ──► ClassReader ──► [ TransformChain ] ──► ClassWriter ──► верификация ──► определённый класс
     │                                  │                                     │
 сохраняется                     упорядоченные,                        CheckClassAdapter
  (откат)                        чистые трансформеры                   + повторная верификация JVM
```

1. **Чтение** — `ClassReader` разбирает исходные байты. Исходный `byte[]` сохраняется
   на время трансформации, поэтому любой сбой обратим.
2. **Трансформация** — упорядоченная `TransformChain` из независимых
   `ClassTransformer` обходит класс. Каждый трансформер — чистая функция
   `(ClassNode) → ClassNode` без разделяемого изменяемого состояния, что позволяет
   параллельное выполнение по классам на виртуальных потоках.
3. **Запись** — `ClassWriter` с `COMPUTE_FRAMES` выдаёт новые байты. Вычисление кадров
   — это стоимость фазы загрузки, которую мы принимаем однократно; она никогда не
   затрагивает фазу выполнения.
4. **Верификация** — `CheckClassAdapter.verify()` плюс повторная верификация JVM.
   Определяется только класс, прошедший обе; иначе — откат ().

## 3. Контракт трансформера

```java
public interface ClassTransformer {              // открытый SPI, см. примечание ниже

    /** Плотный приоритет, назначаемый при сборке. Меньший — раньше. Не зашит в коде. */
    int order();

    /** Истина, если трансформеру есть что делать с классом — дешёвый предфильтр. */
    boolean handles(ClassContext context);

    /** Применить трансформацию; изменяет context.node() на месте, сообщает через TransformResult. */
    TransformResult apply(ClassContext context);

    /** Стабильный id для диагностики; по умолчанию — простое имя класса. */
    default String id() { return getClass().getSimpleName(); }
}
```

> **Проектное примечание (реализовано).** Ранний черновик намечал это как `sealed`.
> Намеренно сделан **открытый SPI**: загрузчик — а позднее и моды — должны поставлять свои
> трансформеры из *других* модулей, не перечисляемых в `aetherium-bytecode`. Модульность
> обеспечивается правилом зависимостей, а не запечатыванием: реализации могут зависеть
> только от `core` + ASM. `ClassContext` несёт разобранный `ClassNode`, поэтому
> `handles`/`apply` принимают контекст (а не сырой узел).

`TransformResult` **является** sealed-типом: `Applied(ClassNode)`, `Skipped(reason)` или
`Failed(diagnostic)`. Исчерпывающее сопоставление с образцом в драйвере движка убирает
защитные ветки и делает каждый исход явным.

## 4. Понижение диспетчеризации (ключевая трансформация)

`DispatchLoweringTransformer` находит каждый `INVOKESTATIC` к настроенному абстрактному
владельцу API и заменяет его на `invokedynamic` к общему bootstrap, передавая **плотный
целочисленный ID** символа (читается из манифеста символов `aetherium-core`, *а не*
литерал в трансформере). Рантайм-классы — в `org.aetherium.bytecode.runtime`:

- `AetheriumBootstraps.bootstrapDispatch(Lookup, String, MethodType, int id)` разрешает
  `DispatchTable.handle(id)` и возвращает `ConstantCallSite`.
- `DispatchTable` — плоский `MethodHandle[]`, устанавливаемый один раз на фазе загрузки;
  `handle(id)` — голый индекс массива.

Итог: однократная линковка, затем встроенные JIT прямые вызовы. Добавление загрузчика
меняет только установленную таблицу, но не трансформер — контракт отсутствия жёсткого
кодирования. (Проверено `aetherium-cli selftest`: пониженный вызов `compute(21)`
маршрутизируется через таблицу и возвращает `42`.)

## 5. Обработка ошибок и откат

- **Предфильтр** (`handles`) избегает обработки классов без ссылок на API —
  большинство классов вообще не переписывается.
- **Изоляция по классам**: каждый класс трансформируется в собственном виртуальном
  потоке с таймаутом. Исключение / таймаут / провал верификации → структурированная
  диагностика + откат к сохранённому исходному `byte[]`. Один плохой класс никогда не
  прерывает запуск.
- **Фиксация версии class-файла**: конструкции новее понимаемых движком вызывают
  *пропуск с диагностикой*, а не угадывание.

## 6. Производительность и память

- Фаза загрузки: `O(n)` от классов × трансформеров, параллелится по ядрам.
- Фаза выполнения: `O(1)` на вызов API (связанный `invokedynamic`). Без рефлексии,
  без боксинга.
- Память: временные `ClassNode` освобождаются после записи; сохраняется только
  таблица диспетчеризации (несколько КБ). Сохранённые оригиналы сбрасываются после
  успешного определения класса.

## 7. Безопасность (соответствие CIA)

- **Целостность** — двойная верификация перед `defineClass`; трансформации над
  копиями.
- **Доступность** — таймауты + изоляция по классам + гарантированный откат.
- **Конфиденциальность** — трансформеры получают `ClassContext` с вычищенными путями
  хоста; они не могут читать вне переданного им графа классов.
