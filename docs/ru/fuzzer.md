# Fuzzer — упрочнение поверхности SPIR-V + WASM

*Русский. Английская версия: [`../en/fuzzer.md`](../en/fuzzer.md).*

`aetherium-fuzzer` — агрессивный детерминированный фаззер для двух по-настоящему небезопасных
поверхностей фреймворка: **компилятора Java→SPIR-V** ([`compute.md`](compute.md)) и
**polyglot-песочницы/моста WASM** ([`wasm.md`](wasm.md)). Его задача — доказать, что *никакой*
некорректный бинарь, нелегальный опкод или запрос памяти вне границ не уронит JVM или хост-ОС: любой
враждебный вход обязан проявиться чистым контрактным исключением.

## Как это работает

Каждый [`FuzzTarget`](../../aetherium-fuzzer/src/main/java/org/aetherium/fuzzer/FuzzTarget.java) прогоняет
одну точку входа одним случайным случаем и объявляет, какой тип исключения — его *документированный*
отказ; `FuzzEngine` классифицирует всё прочее как краш. Так как каждый случай перехвачен — включая
`Error` — успешная кампания ровно эквивалентна «JVM пережила любой вход». Проверки границ FFM превращают
доступ вне границ в `IndexOutOfBoundsException`, а не нативный segfault, поэтому перехваченный throwable
*и есть* доказательство. Случаи семенуются из `(сид кампании, имя цели, итерация)`, поэтому любую находку
можно воспроизвести по её сиду.

Враждебные входы смещены к границам, реально ломающим декодеры (пустые, огрызки 1–3 байта, длины не
кратные слову, валидная-магия-и-мусор, инверсии битов известного-хорошего бинаря), а не плоские случайные
блобы, отвергаемые на первом байте.

## Цели

| Цель | Прогоняет | Чистый отказ |
|------|-----------|--------------|
| `spirv.wrap+verify+dispatch` | `SpirvModule.wrap` + все аксессоры заголовка + `verify()` + диспетч | **нет** — аксессоры тотальны |
| `compute.compileBytes(ASM)` | front-end разбора класса ASM (вкл. инверсии реальных ядер) | `UnsupportedShaderException` |
| `wasm.loadBytes(magic)` | валидатор магии `.wasm` | `IllegalArgumentException` |
| `wasm.bridge.runPhysics(OOB)` | мост `StructArena`↔WASM с OOB-размерами и плохими ядрами | `IndexOutOfBoundsException` |

## Выполняется на каждой сборке

Кампания — обычный JUnit-тест
([`FuzzerCheckTest`](../../aetherium-fuzzer/src/test/java/org/aetherium/fuzzer/FuzzerCheckTest.java)),
поэтому выполняется автоматически при `./gradlew check`. Он утверждает ноль неожиданных throwable **и**
что кампания реально достигла путей контрактного отказа (фаззер, подающий только игнорируемые входы,
ничего не доказывает).

## Найденные баги (исправлены)

Построение целей выявило три реальных дефекта надёжности в коде до фазы 16, все исправлены — фаззер
служит их постоянным регрессионным стражем:

1. **Аксессоры заголовка SPIR-V бросали на усечённом входе.** `magic()`/`version()`/`idBound()`/
   `headerHex()` читали фиксированные смещения слов без проверки границ, поэтому внешний или усечённый
   бинарь бросал `IndexOutOfBoundsException`. Теперь они безопасны по границам (чтение вне диапазона
   даёт `0`); авторитет о корректности — у `verify()`. Появился публичный `SpirvModule.wrap(byte[])`.
2. **Компилятор «протекал» сырыми исключениями ASM.** `ClassReader` бросает
   `ArrayIndexOutOfBoundsException` / `IllegalArgumentException` на не-класс; они уходили из front-end.
   Новый `compileBytes(byte[])` нормализует любой сбой разбора в `UnsupportedShaderException`, а
   неположительный `localSizeX` отвергается так же, а не «протекает» IAE из построителя.
3. **Мост WASM «протекал» off-heap память на каждый вызов.** `runPhysics` аллоцировал свежий сегмент
   линейной памяти в долгоживущую confined-арену на каждый вызов, поэтому плотный per-tick / фаззинг-цикл
   растил нативную память неограниченно. Теперь переиспользуется растущий по нужде scratch-буфер,
   ограниченный максимумом.

## Доказательство

```bash
aetherium fuzz            # по умолчанию 10000 случаев/цель
aetherium fuzz 50000      # сильнее
```

Успешный прогон сообщает по целям счётчики случаев/обработано/отклонено/крашей, суммарные чистые отказы
(доказательство, что пути отказа достигнуты) и **0 неожиданных крашей**.
